# ユーザーストーリー - AdventureWorks 購買管理システム

## 概要

本ドキュメントは、AdventureWorks 購買管理システムのユーザーストーリーを記述します。ビジネスユースケースとシステムユースケースから導出された、アジャイル開発で使用するユーザーストーリーをまとめています。

---

## エピック：購買プロセス効率化

### EP001: 再発注プロセス自動化

**ゴール**: 在庫不足リスクを最小化し、購買担当者の作業効率を向上させる

**ビジネス価値**: 在庫切れによる機会損失の防止、購買業務の効率化、適切な在庫水準の維持

---

## ユーザーストーリー

### US001: 要再発注製品の確認

**As a** 購買担当者
**I want to** 要再発注が必要な製品の一覧を確認できる
**So that** 在庫切れを防ぎ、効率的に発注計画を立てられる

**受け入れ基準**:
- [ ] 要再発注製品一覧画面が表示できる
- [ ] 製品名、ベンダー名、現在在庫数量、推奨発注数量が表示される
- [ ] 単価と小計金額が表示される
- [ ] リードタイムと平均配送日数が表示される
- [ ] 製品をベンダー別にグループ化して表示できる
- [ ] 要再発注製品が存在しない場合は適切なメッセージが表示される

**ストーリーポイント**: 5

**関連UC**: UC001, BUC001

**備考**: RequiringPurchaseProduct エンティティの表示機能

---

### US002: 発注対象製品の選択

**As a** 購買担当者
**I want to** 要再発注製品一覧から実際に発注する製品を選択できる
**So that** 必要な製品のみを効率的に発注できる

**受け入れ基準**:
- [ ] 製品を個別に選択できる
- [ ] 選択した製品が視覚的にハイライトされる
- [ ] 同一ベンダーの関連製品が自動的にハイライトされる
- [ ] 製品が未選択の場合は発注ボタンが無効化される
- [ ] 「発注する」ボタンをクリックして次の画面に進める

**ストーリーポイント**: 3

**関連UC**: UC002, BUC001

**備考**: UI インタラクション機能

---

### US003: 発注の作成

**As a** 購買担当者
**I want to** 選択した製品に対して正式な発注を作成できる
**So that** ベンダーに対して正確な発注情報を送信できる

**受け入れ基準**:
- [ ] 再発注画面で発注内容を確認・修正できる
- [ ] 発注数量を調整できる
- [ ] 配送方法を選択できる
- [ ] 納期希望日を設定できる
- [ ] 特記事項を入力できる
- [ ] 発注金額が自動計算される（小計、税額、送料、総額）
- [ ] 発注内容を確定してデータベースに保存できる
- [ ] 発注完了後にメッセージが表示される

**ストーリーポイント**: 8

**関連UC**: UC003, BUC002

**備考**: PurchaseOrder エンティティの作成機能

---

### US004: 発注金額の自動計算

**As a** 購買担当者
**I want to** 発注作成時に金額が自動計算される
**So that** 計算ミスを防ぎ、正確な発注金額を確認できる

**受け入れ基準**:
- [ ] 発注数量の変更時に小計が自動更新される
- [ ] 小計の合計が自動計算される
- [ ] 税額が自動計算される
- [ ] 送料が自動取得・設定される
- [ ] 総額（小計+税額+送料）が自動計算される
- [ ] 単価未設定の場合は警告メッセージが表示される
- [ ] 計算結果がリアルタイムで画面に反映される

**ストーリーポイント**: 5

**関連UC**: UC004, BUC002

**備考**: Dollar 値オブジェクトの計算機能

---

### US005: 発注の承認

**As a** 購買マネージャー
**I want to** 購買担当者が作成した発注を承認または差し戻しできる
**So that** 適切な購買統制を実現し、コスト管理ができる

**受け入れ基準**:
- [ ] 承認待ち発注一覧が表示できる
- [ ] 発注詳細情報（ベンダー、総額、明細）を確認できる
- [ ] 承認基準との照合結果が表示される
- [ ] 過去の発注履歴と比較できる
- [ ] ワンクリックで承認を実行できる
- [ ] 差し戻し時に理由を入力できる
- [ ] 承認/差し戻し結果が購買担当者に通知される
- [ ] 発注状態が「承認済み」に更新される

**ストーリーポイント**: 8

**関連UC**: UC005, BUC003

**備考**: OrderStatus の状態管理機能

---

### US006: 在庫レベルの確認

**As a** 在庫管理担当者
**I want to** 全製品の在庫レベルを確認できる
**So that** 適切なタイミングで再発注要求を作成できる

**受け入れ基準**:
- [ ] 全製品の在庫状況が分類表示される
- [ ] 在庫状況の分類（正常、要注意、要再発注、在庫切れ）ができる
- [ ] 各製品の現在在庫数量が表示される
- [ ] 在庫閾値との比較結果が表示される
- [ ] 安全在庫量が表示される
- [ ] 過去の使用実績が確認できる
- [ ] 未完了発注数量が表示される
- [ ] 要再発注製品が特定できる

**ストーリーポイント**: 8

**関連UC**: UC006, BUC004

**備考**: 在庫管理システムとの連携機能

---

### US007: 再発注要求の作成

**As a** 在庫管理担当者
**I want to** 要再発注製品について購買部門に要求を作成できる
**So that** 適切な在庫水準を維持できる

**受け入れ基準**:
- [ ] 要再発注製品が自動的に特定される
- [ ] 製品ごとの推奨発注数量が自動計算される
- [ ] 再発注要求データが作成される
- [ ] 購買部門に自動通知が送信される
- [ ] 再発注要求が記録として保存される
- [ ] 緊急在庫切れの場合は緊急通知が送信される

**ストーリーポイント**: 5

**関連UC**: UC007, BUC004

**備考**: 自動化された通知機能

---

### US008: 入荷の処理

**As a** 在庫管理担当者
**I want to** 発注済み製品の入荷を処理できる
**So that** 正確な在庫管理と発注ステータスの更新ができる

**受け入れ基準**:
- [ ] 入荷予定発注一覧が表示できる
- [ ] 発注詳細情報を確認できる
- [ ] 実際の入荷数量を入力できる
- [ ] 入荷日を記録できる
- [ ] 検査結果を入力できる
- [ ] 品質状態を記録できる
- [ ] 入荷数量の妥当性がチェックされる
- [ ] 在庫数量が自動更新される
- [ ] 発注状態が「入荷完了」に更新される
- [ ] 関係者に入荷完了通知が送信される

**ストーリーポイント**: 8

**関連UC**: UC008, BUC005

**備考**: 在庫更新とステータス管理機能

## Definition of Done（完了の定義）

各ユーザーストーリーが「完了」とみなされるための基準：

### 機能要件
- [ ] すべての受け入れ基準が満たされている
- [ ] ユニットテストが作成され、すべて合格している
- [ ] 統合テストが作成され、すべて合格している
- [ ] UI/UXが要求に従って実装されている

### 品質要件
- [ ] コードレビューが完了している
- [ ] セキュリティ要件（認証・認可）が実装されている
- [ ] エラーハンドリングが適切に実装されている
- [ ] ログ出力が適切に実装されている

### ドキュメント要件
- [ ] APIドキュメント（該当する場合）が更新されている
- [ ] ユーザーマニュアル（該当する場合）が更新されている
- [ ] 技術ドキュメントが更新されている

### テスト要件
- [ ] 自動テストが CI/CD パイプラインで実行される
- [ ] テストカバレッジが基準を満たしている
- [ ] 手動テストでの確認が完了している
