# システムユースケース - AdventureWorks 購買管理システム

## 概要

本ドキュメントは、AdventureWorks 購買管理システムのシステムユースケースを詳細化したものです。ビジネスユースケースから導出されたシステムレベルの機能要件を完全形式で記述します。

---

## UC001: 要再発注製品を確認する💾🌊

**使用時のコンテキスト**: 購買担当者が要再発注製品一覧画面で、在庫不足の製品を確認し、発注対象を選択する

**スコープ**: AdventureWorks 購買管理システム

**レベル**: ユーザー目的

**主アクター**: 購買担当者

**利害関係者と利益**:
- 購買担当者: 要再発注製品を効率的に確認できる
- システム: 正確な在庫データに基づいて要再発注製品リストを提供する

**事前条件**:
- ユーザーがシステムにログイン済みである
- 在庫データが最新に更新されている
- 製品マスタに在庫閾値が設定されている

**最低保証**: 要再発注製品一覧が表示される

**成功保証時**: 購買担当者が発注対象製品を選択し、次の処理に進める状態となる

**トリガー**: 購買担当者が要再発注製品確認画面を表示

**主成功シナリオ**:
1. 購買担当者が要再発注製品一覧画面にアクセスする
2. システムが RequiringPurchaseProductQuery を実行する
3. システムが要再発注製品データを取得する
4. システムが製品情報を画面に表示する：
   - ベンダー名
   - 製品カテゴリ・サブカテゴリ名
   - 製品名
   - 推奨発注数量
   - 単価と小計
   - 配送日数・平均リードタイム
   - 現在在庫数量・未完了発注数量
5. 購買担当者が製品を選択する
6. システムが選択された製品の詳細情報を表示する
7. システムが選択状態を保持する

**拡張**:
- 3a. 要再発注製品が存在しない場合:
  - システムが「現在要再発注製品はありません」メッセージを表示
  - メイン画面に戻る
- 5a. 製品詳細が必要な場合:
  - システムが製品マスタ詳細画面を表示
  - 確認後に一覧画面に戻る
- 2a. データ取得エラーの場合:
  - システムがエラーメッセージを表示
  - 再試行オプションを提供

**技術およびデータのバリエーションリスト**:
- 2a. データソース: SQL Server / 外部API / キャッシュ
- 4a. 表示順序: ベンダー別 / 緊急度順 / 金額順
- 4b. 表示形式: グリッド表示 / カード表示

**関連情報**:
- RequiringPurchaseProduct エンティティ仕様
- IRequiringPurchaseProductQuery インターフェース仕様

## UC002: 発注対象製品を選択する💾🐟

**使用時のコンテキスト**: 要再発注製品一覧から、実際に発注を行う製品を選択し、発注処理に進む

**スコープ**: AdventureWorks 購買管理システム

**レベル**: サブ機能

**主アクター**: 購買担当者

**利害関係者と利益**:
- 購買担当者: 適切な製品を効率的に選択できる
- システム: 選択された製品情報を正確に保持する

**事前条件**:
- 要再発注製品一覧が表示されている
- 製品データが正常に取得済みである

**最低保証**: 製品選択状態が保持される

**成功保証時**: 選択された製品群で発注作成処理に進める

**トリガー**: 購買担当者が製品を選択またはベンダーを選択

**主成功シナリオ**:
1. 購買担当者が要再発注製品一覧で製品を選択する
2. システムが同一ベンダーの関連製品をハイライト表示する
3. 購買担当者が「発注する」ボタンをクリックする
4. システムがベンダー情報を取得する
5. システムが選択製品とベンダー情報を保持する
6. システムが再発注画面に遷移する

**拡張**:
- 1a. 製品が選択されていない場合:
  - システムが「製品を選択してください」メッセージを表示
  - 発注ボタンを無効化
- 4a. ベンダー情報取得エラーの場合:
  - システムがエラーメッセージを表示
  - ベンダーマスタメンテナンス画面への遷移オプションを提供

**技術およびデータのバリエーションリスト**:
- 1a. 選択方式: 単一選択 / 複数選択 / ベンダー単位選択
- 4a. データ取得方式: 同期取得 / 非同期取得

**関連情報**:
- Vendor エンティティ仕様
- IVendorRepository インターフェース仕様

## UC003: 発注を作成する💾🌊

**使用時のコンテキスト**: 選択された製品群に対して正式な発注を作成し、承認処理またはベンダーへの送信を行う

**スコープ**: AdventureWorks 購買管理システム

**レベル**: ユーザー目的

**主アクター**: 購買担当者

**利害関係者と利益**:
- 購買担当者: 正確で効率的な発注作成ができる
- ベンダー: 正確な発注情報を受信できる
- システム: 発注データの整合性を保持する

**事前条件**:
- 発注対象製品が選択済みである
- ベンダー情報が有効である
- ユーザーが発注権限を持つ

**最低保証**: 発注データがシステムに記録される

**成功保証時**: 発注が作成され、承認プロセスまたはベンダー送信が完了する

**トリガー**: 購買担当者が再発注画面で発注作成を実行

**主成功シナリオ**:
1. システムが再発注画面を表示する
2. 購買担当者が発注内容を確認・修正する：
   - 発注数量
   - 配送方法
   - 納期希望日
   - 特記事項
3. システムが発注金額を自動計算する
4. 購買担当者が発注を確定する
5. システムが PurchaseOrder エンティティを作成する
6. システムが発注をデータベースに保存する
7. システムが承認が必要かチェックする
8. システムが発注完了メッセージを表示する
9. システムがメイン画面に戻る

**拡張**:
- 7a. 承認が必要な場合:
  - システムが承認待ち状態で発注を保存
  - 承認者に通知を送信
- 7b. 自動承認の場合:
  - システムが発注を承認済み状態で保存
  - ベンダーに発注書を送信
- 6a. データベース保存エラーの場合:
  - システムがエラーメッセージを表示
  - 再試行オプションを提供
- 3a. 金額計算エラーの場合:
  - システムが警告メッセージを表示
  - 手動計算モードに切り替え

**技術およびデータのバリエーションリスト**:
- 5a. 発注作成方式: ファクトリーパターン / ビルダーパターン
- 7a. 承認判定基準: 金額ベース / ベンダーベース / ユーザー権限ベース
- 6a. 永続化方式: 即座保存 / トランザクション管理 / バッチ保存

**関連情報**:
- PurchaseOrder エンティティ仕様
- PurchaseOrderBuilder クラス仕様
- IPurchaseOrderRepository インターフェース仕様

## UC004: 発注金額を計算する💾🐟

**使用時のコンテキスト**: 発注作成時に小計、税額、送料、総額を自動計算する

**スコープ**: AdventureWorks 購買管理システム

**レベル**: サブ機能

**主アクター**: システム

**利害関係者と利益**:
- 購買担当者: 正確な発注金額を確認できる
- 経理担当者: 正確な会計処理ができる

**事前条件**:
- 発注明細が入力済みである
- 製品単価が設定されている
- 税率・送料が設定されている

**最低保証**: 基本的な金額計算が実行される

**成功保証時**: 正確な発注総額が算出される

**トリガー**: 発注数量または内容の変更

**主成功シナリオ**:
1. システムが発注明細データを取得する
2. システムが各明細の小計を計算する（単価 × 数量）
3. システムが小計の合計を計算する
4. システムが税額を計算する（小計 × 税率）
5. システムが送料を取得する
6. システムが総額を計算する（小計 + 税額 + 送料）
7. システムが計算結果を画面に反映する

**拡張**:
- 2a. 単価が未設定の場合:
  - システムが警告メッセージを表示
  - ゼロで計算を継続
- 4a. 税率が未設定の場合:
  - システムが標準税率を適用
  - 警告メッセージを表示
- 5a. 送料が計算できない場合:
  - システムがゼロで計算
  - 手動入力を促す

**技術およびデータのバリエーションリスト**:
- 4a. 税率適用方式: 標準税率 / 製品別税率 / 地域別税率
- 5a. 送料計算方式: 固定料金 / 重量ベース / 距離ベース

**関連情報**:
- Dollar 値オブジェクト仕様
- 税率計算ルール

## UC005: 発注を承認する💾🌊

**使用時のコンテキスト**: 購買マネージャーが承認待ちの発注を確認し、承認または差し戻しを行う

**スコープ**: AdventureWorks 購買管理システム

**レベル**: ユーザー目的

**主アクター**: 購買マネージャー

**利害関係者と利益**:
- 購買マネージャー: 効率的な承認プロセスを実行できる
- 購買担当者: 承認結果を迅速に受け取れる
- 経営陣: 適切な購買統制を確保できる

**事前条件**:
- 承認待ち発注が存在する
- 購買マネージャーがログイン済みである
- 適切な承認権限を持つ

**最低保証**: 承認結果が記録される

**成功保証時**: 発注が承認され、次のプロセスに進める状態となる

**トリガー**: 購買マネージャーが承認待ち発注を確認

**主成功シナリオ**:
1. 購買マネージャーが承認待ち発注一覧を表示する
2. システムが承認待ち発注を表示する
3. 購買マネージャーが対象発注を選択する
4. システムが発注詳細を表示する
5. 購買マネージャーが発注内容を確認する
6. 購買マネージャーが承認を実行する
7. システムが承認記録を保存する
8. システムが発注状態を「承認済み」に更新する
9. システムが承認完了通知を送信する

**拡張**:
- 6a. 承認を拒否する場合:
  - 購買マネージャーが拒否理由を入力
  - システムが発注状態を「差し戻し」に更新
  - 発注者に拒否通知を送信
- 7a. 承認記録の保存エラーの場合:
  - システムがエラーメッセージを表示
  - 再試行オプションを提供
- 2a. 承認待ち発注が存在しない場合:
  - システムが「承認待ち発注はありません」メッセージを表示

**技術およびデータのバリエーションリスト**:
- 6a. 承認方式: ワンクリック承認 / 電子署名 / 二要素認証
- 9a. 通知方式: システム内通知 / 電子メール / SMS

**関連情報**:
- OrderStatus 列挙型仕様
- 承認ワークフロー仕様

**レベル**: ユーザー目的

**主アクター**: 在庫管理担当者

**利害関係者と利益**:
- 在庫管理担当者: 在庫状況を正確に把握できる
- 購買担当者: 正確な再発注要求を受け取れる

**事前条件**:
- 在庫データが最新に更新されている
- 製品マスタに在庫閾値が設定されている

**最低保証**: 現在の在庫状況が表示される

**成功保証時**: 要再発注製品が特定され、適切な通知が行われる

**トリガー**: 在庫管理担当者が在庫確認を実行

**主成功シナリオ**:
1. 在庫管理担当者が在庫確認画面を表示する
2. システムが全製品の在庫データを取得する
3. システムが各製品の在庫レベルを閾値と比較する
4. システムが在庫状況を分類する
5. システムが要再発注製品を特定する
6. システムが在庫状況を画面に表示する

**技術およびデータのバリエーションリスト**:
- 2a. データソース: リアルタイムDB / バッチ更新データ

## UC008: 入荷を処理する💾🌊

**使用時のコンテキスト**: 発注済み製品の入荷時に、数量確認と在庫更新を行う

**スコープ**: AdventureWorks 購買管理システム

**レベル**: ユーザー目的

**主アクター**: 在庫管理担当者

**利害関係者と利益**:
- 在庫管理担当者: 正確かつ迅速な入荷処理ができる
- 購買担当者: 発注した製品の入荷を確認できる
- 経理担当者: 正確な支払処理情報を取得できる

**事前条件**:
- 入荷予定の発注が存在する
- 物理的な製品が到着している
- 検査が完了している

**最低保証**: 入荷記録が保存される

**成功保証時**: 在庫が正確に更新され、関係者に通知される

**トリガー**: 製品の物理的到着と検査完了

**主成功シナリオ**:
1. 在庫管理担当者が入荷処理画面を表示する
2. システムが入荷予定発注一覧を表示する
3. 在庫管理担当者が対象発注を選択する
4. システムが発注詳細を表示する
5. 在庫管理担当者が実入荷情報を入力する
6. システムが入荷数量の妥当性をチェックする
7. 在庫管理担当者が入荷処理を確定する
8. システムが在庫数量を更新する
9. システムが発注状態を更新する
10. システムが関係者に入荷完了通知を送信する

**拡張**:
- 6a. 入荷数量が発注数量と異なる場合:
  - システムが差異理由入力画面を表示
  - 購買担当者に差異通知を送信
- 8a. 在庫更新エラーの場合:
  - システムがロールバック処理を実行
  - エラーログを出力し、手動処理を促す
- 5a. 品質検査不合格の場合:
  - システムが不合格品処理画面を表示
  - 返品・廃棄処理オプションを提供

**技術およびデータのバリエーションリスト**:
- 8a. 在庫更新方式: リアルタイム更新 / バッチ更新
- 10a. 通知対象: 発注者のみ / 関係者全員 / 設定による
- 6a. 妥当性チェック: 数量のみ / 数量と金額 / 品質も含む

**関連情報**:
- 入荷処理仕様
- 在庫更新仕様
- 通知システム仕様
